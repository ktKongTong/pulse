# Swift Export enum-return crash (KT-83730)

## Symptom

When a Kotlin function (top-level or member) returns a Kotlin enum value
to Swift via Swift Export, the generated `init(__externalRCRefUnsafe:)`
on the corresponding Swift enum falls through to `fatalError()` and the
app aborts.

The crash surfaces as something like:

```
PulseBarShared/PulseBarShared.swift:2882: Fatal error
```

pointing at the `default: fatalError()` branch inside the Swift enum's
`init(__externalRCRefUnsafe: Swift.UnsafeMutableRawPointer!, ...)`
initializer.

## Upstream tracker

- YouTrack: <https://youtrack.jetbrains.com/issue/KT-83730>

## Why it happens

The generated Swift enum looks like this (abbreviated, from
`PulseBarShared.swift`):

```swift
public enum ConnectionRuntimeStatus: _KotlinBridgeable, CaseIterable,
    LosslessStringConvertible, RawRepresentable {
    case Connected
    case Disconnected
    case Reconnecting

    public init(__externalRCRefUnsafe: UnsafeMutableRawPointer!, ...) {
        switch __externalRCRefUnsafe {
        case io_github_kt_pulsebar_core_presentation_ConnectionRuntimeStatus_Connected():
            self = .Connected
        case io_github_kt_pulsebar_core_presentation_ConnectionRuntimeStatus_Disconnected():
            self = .Disconnected
        case io_github_kt_pulsebar_core_presentation_ConnectionRuntimeStatus_Reconnecting():
            self = .Reconnecting
        default: fatalError()
        }
    }
}
```

The Kotlin-side function returns a C pointer that Swift Export passes
into this initializer. The cached case pointers in the `switch` come
from calling the per-case C helpers (`..._Connected()` etc.) at
initializer time. For enums where the Kotlin side's returned pointer
does **not** match any of those case helper pointers, the switch falls
through and crashes.

Every Swift enum generated by Swift Export has this shape, so this bug
is latent for all `PulseBar*` enums the bridge returns to Swift (we hit
it first with `ConnectionRuntimeStatus`).

## Workaround

Return the enum's `.name` (or some stable string) from the Kotlin
function and parse it locally in Swift. The string path doesn't go
through `init(__externalRCRefUnsafe:)` so it sidesteps the bug.

**Kotlin:**

```kotlin
// Before (crashes at runtime):
fun resolveDraftConnectionStatus(...): ConnectionRuntimeStatus = ...

// After:
fun resolveDraftConnectionStatus(...): String = computed.name
```

**Swift:**

```swift
let name = ExportedKotlinPackages.io.github.kt.pulsebar.core.presentation
    .resolveDraftConnectionStatus(endpoint: e, sync: s, manuallyDisconnected: d)
switch name {
case "Connected": return .Connected
case "Reconnecting": return .Reconnecting
default: return .Disconnected
}
```

## Other affected call-sites to audit

Any enum getter on a Kotlin class exported to Swift goes through the
same path. In PulseBar:

- `PulseBarLiveListenStats.connectionState`
  (`PulseBarLiveListenConnectionState`) — currently latent because
  nothing reads it during app startup; will crash if the Live Listen
  pane ever reads it. Defensive fix: read `connectionStateName: String`
  sibling field (already exposed by the bridge) and parse locally.
- `PulseBarEndpointConfig.transport` (`PulseBarTransport`) — latent,
  no Swift reader.
- `PulseBarConfig.interactionExecutionMode` /
  `interactionPlaybackMode` — latent, no Swift reader.
- `PulseBarPlaybackCommand` — we pass it *from* Swift *to* Kotlin,
  which exercises the opposite direction (`__externalRCRef()`), not
  the crashing init. Safe so far.

## Detection

`scripts/check-pulse.sh` launches the binary directly with stderr
captured to `/tmp/pulse-stderr.log`, waits 10 seconds, and reports
whether the process is still alive. `dev-pulse-native.sh --verify` uses
`pgrep` and races past fast crashes; it's insufficient for catching
this bug. Use `check-pulse.sh` when touching enum-bridge code.

## Remove the workaround when

The YouTrack issue above closes, we bump to that Kotlin / Swift Export
version, and a full clean rebuild + `scripts/check-pulse.sh` passes
without the string detour.
